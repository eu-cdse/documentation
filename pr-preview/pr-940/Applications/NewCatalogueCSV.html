Copernicus CSV Catalogue API — User Guide

OData 4.0 interface for the Copernicus daily catalogue index

Overview

The CSV Catalogue OData API provides access to daily-regenerated Copernicus satellite data index files hosted by the Copernicus Data Space Ecosystem. Each CSV file contains a complete list of available data products for one satellite platform on a given day.

The API follows the OData 4.0 standard. All query options are prefixed with $ and separated by &. No authentication is required.

Base URL

https://api.csv.dataspace.copernicus.eu/odata/v1

Typical workflow

  1. Query /Csvs with $filter to find the files you need.
  2. Download individual files with /$value, or a batch with POST /Csvs/Download.
  3. Verify integrity with the sha256_hash field.

Each step is covered below.

Note

Output blocks in this guide are illustrative examples of response shape, not live captures. Actual IDs, sizes, and counts change daily.

Before you start

The examples need requests. The tabular displays also use pandas, which is a convenience for this guide rather than a requirement of the API.

pip install requests pandas

Every Python snippet below assumes this setup cell has run:

import requests
import pandas as pd

BASE = "https://api.csv.dataspace.copernicus.eu/odata/v1"
Quote your URLs in the shell

Every OData query option starts with $, and bash and zsh expand $ inside double quotes. Pasting a URL into curl "...?$filter=..." silently sends an unfiltered request, because the shell replaces $filter and $top with empty strings before curl ever runs. There is no error — you just get the wrong results.

Use single quotes, or let curl build the query string:

curl -sG 'https://api.csv.dataspace.copernicus.eu/odata/v1/Csvs' \
     --data-urlencode "\$filter=Collection/Name eq 'SENTINEL-1'" \
     --data-urlencode "\$top=3"

The bare GET /Csvs?... lines throughout this guide show the logical request. They are not URL-encoded and are not meant to be pasted straight into a shell.

Quickstart

Find yesterday’s SENTINEL-2 catalogue file, download it, and verify it:

import hashlib
import pathlib
from datetime import date, timedelta

BASE = "https://api.csv.dataspace.copernicus.eu/odata/v1"
day = date.today() - timedelta(days=1)

# 1. Find it
entry = requests.get(
    f"{BASE}/Csvs",
    params={
        "$filter": f"Collection/Name eq 'SENTINEL-2' and ContentDate eq {day}",
        "$top": 1,
    },
).json()["value"][0]

# 2. Download it
out = pathlib.Path(entry["display_name"])
with requests.get(f"{BASE}/Csvs({entry['id']})/$value", stream=True) as resp:
    resp.raise_for_status()
    with out.open("wb") as fh:
        for chunk in resp.iter_content(chunk_size=65536):
            fh.write(chunk)

# 3. Verify it
digest = hashlib.sha256(out.read_bytes()).hexdigest()
assert digest == entry["sha256_hash"], "checksum mismatch"
print(f"{out} - {out.stat().st_size} bytes, checksum OK")

The rest of this guide covers each step in detail.

What a catalogue file contains

A catalogue file is a semicolon-delimited CSV listing every product available for one collection on one day. Data values are double-quoted, the header row is not, and dates are ISO 8601 with milliseconds.

Column Description
id Product UUID in the Copernicus Data Space catalogue
name Product name (for Sentinel, a .SAFE product)
contentlength Product size in bytes
ingestiondate When the product was ingested
contentdateend End of the product’s acquisition window
modificationdate When the product record last changed
checksumalgorithm Checksum algorithm, MD5
checksumvalue Product checksum
s3path Object storage location, s3://eodata/...
bbox Product footprint as a WKT POLYGON
Sentinel and CLMS headers differ
Sentinel CLMS
Acquisition start column contentdatestart contentstartdate
Additional column — nominaldate, after contentdateend

The start-date column is spelled differently in each, and CLMS carries one extra column. Parse by column name, never by position, and do not assume a header read from one collection applies to another.

Sentinel header:

id;name;contentlength;ingestiondate;contentdatestart;contentdateend;modificationdate;checksumalgorithm;checksumvalue;s3path;bbox

CLMS header:

id;name;contentlength;ingestiondate;contentstartdate;contentdateend;nominaldate;modificationdate;checksumalgorithm;checksumvalue;s3path;bbox
Note

checksumvalue is an MD5 digest of the product and is unrelated to the sha256_hash field on the catalogue entry, which covers the CSV file itself.

Reading a downloaded file:

df = pd.read_csv("catalogue.csv", sep=";")
print(df.columns.tolist())
print(len(df), "products")

You can inspect the header without downloading the whole file by requesting only the first few kilobytes (see Downloading files for the full Range semantics):

peek = requests.get(
    f"{BASE}/Csvs({entry['id']})/$value", headers={"Range": "bytes=0-2047"}
)
print(peek.status_code)             # 206
print(peek.text.splitlines()[0])    # header row

Filtering

Filterable fields

Only the fields below can be used in a $filter expression. Any other field name is rejected with 422 Unprocessable Entity and the message Unknown filter field: '<name>'.

Field Type Notes
Collection/ID UUID string Quoted, e.g. '430fb64d-…'
Collection/Name string SENTINEL-1, SENTINEL-2, SENTINEL-3, SENTINEL-5P, SENTINEL-6, CLMS
ContentDate Edm.Date Content/validity date. Null for CLMS.
CreatedDate Edm.Date Date the file was added to the catalogue
LastModified Edm.Date Date the CSV content was last changed
attributes/component string CLMS component
attributes/product_types string CLMS product type
attributes/dataset_id string CLMS dataset identifier
attributes/fileformat string CLMS file format
attributes/platform_id string Sentinel platform: A, B, C, D
Important

file_size, name, display_name, and sha256_hash appear in responses but are not filterable. file_size is sortable via $orderby (see Sorting).

Multiple conditions can be combined with and and or. String comparisons are case-sensitive.

r.raise_for_status()
df = pd.DataFrame.from_dict(r.json()["value"])

By content date

ContentDate is the validity date of the catalogue file (one date per file). Sentinel collections always have a ContentDate; CLMS files do not.

Note

Date values in OData filters are unquoted Edm.Date literals — for example ContentDate ge 2024-01-01. String values always use single quotes — Collection/Name eq 'SENTINEL-1'.

Tip

Narrowing the date range to individual months or weeks gives the best query performance.

GET /Csvs?$filter=ContentDate ge 2024-01-01 and ContentDate lt 2024-02-01
r = requests.get(
    f"{BASE}/Csvs",
    params={"$filter": "ContentDate ge 2024-01-01 and ContentDate lt 2024-02-01"},
)
df = pd.DataFrame.from_dict(r.json()["value"])

CreatedDate is the date the file was added to the catalogue. Use it to retrieve files published after a certain date.

By CLMS attributes

CLMS catalogue files carry four attributes describing the dataset: component, product_types, dataset_id, and fileformat.

GET /Csvs?$filter=attributes/component eq 'bio-geophysical'&$top=3
r = requests.get(
    f"{BASE}/Csvs",
    params={"$filter": "attributes/component eq 'bio-geophysical'", "$top": 3},
)
df = pd.DataFrame.from_dict(r.json()["value"])
df[["id", "name", "file_size"]]

To narrow further by product type and file format:

r = requests.get(
    f"{BASE}/Csvs",
    params={
        "$filter": (

A $filter expression is limited to 2000 characters and 20 levels of nesting. Exceeding either returns 422.

Sorting

$orderby accepts exactly two field names:

$orderby field Sorts by
size File size
ContentDate Content / validity date
Important

The sort field is size, not file_size. Any other value returns 422 Invalid $orderby parameter.

Append asc or desc after the field name.

Note

Unlike the OData specification, which defaults to ascending, this API defaults to descending when no direction is given.

Pagination

$top limits the number of results returned (1–1000, default 100). $skip offsets the starting position. Use them together to page through large result sets.

GET /Csvs?$filter=Collection/Name eq 'SENTINEL-1'&$top=100&$skip=100
Important

Page with the largest $top you can. GET /Csvs is limited to 100 requests per 60 seconds, so a collection of ~15,000 entries takes 154 requests at $top=100 — which exceeds the limit partway through — but only 16 at $top=1000. Always handle 429 as well; see Rate limits.

import time

PAGE = 1000        # the $top maximum: fewest requests, least rate-limit pressure
results = []
skip = 0

while True:
    r = requests.get(
        f"{BASE}/Csvs",
        params={
            "$filter": "Collection/Name eq 'SENTINEL-1'",
            "$orderby": "ContentDate desc",
            "$top": PAGE,
            "$skip": skip,
        },
    )
    if r.status_code == 429:
        time.sleep(int(r.headers.get("Retry-After", 10)))
        continue          # retry the same page
    r.raise_for_status()

    batch = r.json()["value"]
    results.extend(batch)
    if len(batch) < PAGE:
        break
    skip += PAGE

df = pd.DataFrame.from_dict(results)
print(len(df), "entries retrieved")
Tip

Pass $orderby when paging. Without an explicit sort the page boundaries are not guaranteed to be stable between requests.

Removed entries

Files withdrawn from the catalogue are removed from the API, not just from listings. Their IDs no longer appear in GET /Csvs or /Csvs/Schema counts. GET /Csvs({id}) and /$value return 404, and a bulk download that names them returns 422 listing the missing IDs. If you store IDs between runs, look them up again rather than assuming they still exist. The same applies to ZIP entries.

Downloading files

Choosing a method

Three endpoints deliver files, with different limits. Pick by how much you need:

You want Use Limits
One file GET /Csvs({id})/$value 60 requests / 60 s
A handful POST /Csvs/Download (one ZIP) 50 files and 50 MB per request
More than a handful Loop over /$value yourself 60 requests / 60 s
Everything GET /Zips(name=...)/$value One ~13 GB archive, 5 requests / 60 s
Important

There is a gap between the bulk endpoint and the full archive. Bulk download caps at 50 files, so anything larger — a month or a year of one collection — has to be fetched by looping over /$value, one file per request, respecting the 60-per-minute limit. Do not reach for the 13 GB archive just because a request of a few hundred files exceeds the bulk cap.

Looping for a mid-sized set:

import time

entries = requests.get(
    f"{BASE}/Csvs",
    params={
        "$filter": (
            "Collection/Name eq 'SENTINEL-2'"
            " and ContentDate ge 2024-06-01 and ContentDate lt 2024-07-01"
        ),
        "$top": 1000,
    },
).json()["value"]

dest = pathlib.Path("sentinel2-june2024")
dest.mkdir(exist_ok=True)

for e in entries:
    target = dest / e["display_name"]
    if target.exists():
        continue                    # resumable: skip what we already have

    while True:                     # wait out the rate limit, don't skip the file
        r = requests.get(f"{BASE}/Csvs({e['id']})/$value", stream=True)
        if r.status_code == 429:
            time.sleep(int(r.headers.get("Retry-After", 10)))
            continue
        r.raise_for_status()
        break

    with target.open("wb") as fh:
        for chunk in r.iter_content(chunk_size=65536):
            fh.write(chunk)

print(len(list(dest.iterdir())), "files in", dest)

Single file

GET /Csvs(ca3438ff-e693-4e86-b00e-7afef3322632)/$value
import pathlib

csv_id = "ca3438ff-e693-4e86-b00e-7afef3322632"

    for chunk in resp.iter_content(chunk_size=65536):
        fh.write(chunk)

print("Downloaded", out.stat().st_size, "bytes")

The response carries Content-Disposition, ETag, and Accept-Ranges: bytes.

The endpoint supports the HTTP Range header for partial downloads, responding with 206 Partial Content plus a Content-Range header:

Range: bytes=0-10485759   # first 10 MB

Both open-ended (bytes=1024-) and suffix (bytes=-1024, the last 1024 bytes) forms are accepted. An end offset beyond the file is clamped to the last byte.

Two failure modes behave differently:

Range header Response
Malformed syntax, or multi-range (bytes=0-99,200-299) Ignored — full file with 200
Unsatisfiable: start at or beyond EOF, start greater than end (bytes=500-100), or bytes=-0 416 Range Not Satisfiable with Content-Range: bytes */<file-size>

Multi-range requests are not supported; only the first form above is honoured.

Bulk download as ZIP

To download multiple CSV files as a single ZIP archive, POST to /Csvs/Download. The request body must contain exactly one of ids or $filter — providing both, or neither, returns 422.

Body field Type Notes
ids list of UUID Mutually exclusive with $filter
$filter string OData filter, same syntax as GET /Csvs
$top integer 1–500, default 50. Only with $filter.
$skip integer Default 0. Only with $filter.
Important

$top accepts up to 500, but a request that resolves to more than 50 files is rejected with 422. In practice, keep $top at 50 or below and page with $skip. The default of 50 already matches the file limit.

By ID list:

resp = requests.post(
    f"{BASE}/Csvs/Download",
    json={
        "ids": [
            "ca3438ff-e693-4e86-b00e-7afef3322632",
            "13f1328b-16be-4c3c-afe4-46e38c87cd8c",
        ]
    },
    stream=True,
)
resp.raise_for_status()
pathlib.Path("csvs.zip").write_bytes(resp.content)

By filter:

resp = requests.post(
    f"{BASE}/Csvs/Download",
    json={
        "$filter": "Collection/Name eq 'SENTINEL-6' and ContentDate ge 2024-06-01",
        "$top": 20,
    },
    stream=True,
)
resp.raise_for_status()
pathlib.Path("s6_june2024.zip").write_bytes(resp.content)
Note

Bulk download is limited to 50 CSV files and a combined 50 MB per request (server defaults). Exceeding either limit returns 422, as does referencing an ID that does not exist — the response body names the missing IDs.

The size limit is reached long before the file limit for large collections. A single SENTINEL-2 file can be 40 MB, so even 20 of them exceed 50 MB. Check file_size in the listing before building a bulk request.

Downloading an archive

By name:

GET /Zips(name=CopernicusCatalogueCSV.zip)/$value

By UUID:

GET /Zips(8e703db1-e370-4500-be00-ea42a89648c9)/$value
Important

The name in a (name=...) path segment is not quoted. Writing Zips(name='CopernicusCatalogueCSV.zip')/$value makes the quotes part of the file name and returns 404. Single quotes are only used for string literals inside $filter expressions.

Resumable download with a progress bar:

import pathlib

import requests
import tqdm  # pip install tqdm

url = f"{BASE}/Zips(name=CopernicusCatalogueCSV.zip)/$value"
out = pathlib.Path("CopernicusCatalogueCSV.zip")

downloaded = out.stat().st_size if out.exists() else 0
headers = {"Range": f"bytes={downloaded}-"} if downloaded else {}

resp = requests.get(url, headers=headers, stream=True)
resp.raise_for_status()
total = int(resp.headers.get("Content-Length", 0)) + downloaded

with out.open("ab") as fh, tqdm.tqdm(
    total=total, initial=downloaded, unit="B", unit_scale=True
) as bar:
    for chunk in resp.iter_content(chunk_size=1048576):
        fh.write(chunk)
        bar.update(len(chunk))
Tip

The full archive is approximately 13 GB and grows daily. Use the Range header or a resumable download tool (curl --continue-at -, wget --continue) to safely resume interrupted transfers.

Integrity verification

Every CSV and ZIP entry includes a sha256_hash field. Verify it after downloading to confirm the file was not corrupted in transit.

import hashlib
import pathlib

csv_id = "ca3438ff-e693-4e86-b00e-7afef3322632"
expected = requests.get(f"{BASE}/Csvs({csv_id})").json()["sha256_hash"]
actual = hashlib.sha256(pathlib.Path("catalogue.csv").read_bytes()).hexdigest()

assert actual == expected, "Integrity check failed!"
print("OK —", actual)

From the shell:

# Linux / macOS

# Windows PowerShell
Get-FileHash catalogue.csv -Algorithm SHA256

Rate limits

Requests are limited per IP address over a 60-second sliding window.

Endpoint Limit (requests / 60 s)
GET /Csvs (list) 100
GET /Csvs({id}) (single entry) 200
GET /Csvs({id})/$value (download) 60
GET /Csvs/Schema 60
POST /Csvs/Download (bulk ZIP) 10
GET /Zips (list) 100
GET /Zips({id}) (single entry) 200
GET /Zips({id})/$value (download) 5

The OData ({id}) and slash /{id} forms of an endpoint share a single counter.

JSON responses (listings, single entries, Schema, metadata) carry the current budget, so clients can throttle before being rejected. File downloads (/$value and POST /Csvs/Download) do not — track your own request rate for those.

Header Meaning
X-RateLimit-Limit Requests permitted in the window
X-RateLimit-Remaining Requests still available

When the limit is exceeded, any endpoint returns 429 Too Many Requests. The response carries a Retry-After header giving the number of seconds to wait, the X-RateLimit-* headers with X-RateLimit-Remaining: 0, and the body {"detail": "Rate limit exceeded"}.

import time


def get_with_retry(url, params=None, max_retries=3):
    for _ in range(max_retries):
        r = requests.get(url, params=params)
        if r.status_code == 429:
            time.sleep(int(r.headers.get("Retry-After", 10)))
            continue
        r.raise_for_status()
        return r
    raise RuntimeError(f"Failed after {max_retries} retries")

A more efficient client watches X-RateLimit-Remaining and slows down before hitting zero, rather than waiting for a 429.

Error responses

Status Meaning
404 Not Found No CSV or ZIP matches the requested ID or name (including entries removed from the catalogue), or the file is missing from storage
406 Not Acceptable $metadata requested with a non-JSON Accept header
416 Range Not Satisfiable Range header valid but outside the file; carries Content-Range: bytes */<file-size>
422 Unprocessable Entity Invalid $filter or $orderby, unknown filter field, $top out of range, both/neither of ids and $filter in a bulk request, or a bulk request exceeding the count or size limit
429 Too Many Requests Rate limit exceeded; see Retry-After
500 Internal Server Error Unhandled server-side failure
503 Service Unavailable Object storage or the rate-limiter backend is temporarily unreachable; retry shortly
Important

The detail field has two different shapes, and a 422 can have either one. Client code that assumes one shape will break on the other.

  • Array of objects — invalid query or body parameters: a malformed or too long $filter, an unknown filter field, an invalid $orderby, or $top/$skip out of range.
  • Plain string — every other error, including the 422s from POST /Csvs/Download that check the request as a whole: both or neither of ids and $filter, too many files, total size over the limit, or unknown IDs.

Parameter validation 422 — array of objects, naming the offending parameter:

{
  "detail": [
    {
      "type": "value_error",
      "loc": ["query", "$filter"],
      "msg": "Unknown filter field: 'file_size'",
      "input": "file_size le 1000000"
    }
  ]
}

404, 429, 500, 503, and bulk-download 422 — a plain string:

{ "detail": "CSV not found" }
{ "detail": "Too many CSVs: 100 exceeds limit of 50" }

Other string values include ZIP not found, File not found in storage, Rate limit exceeded, Storage unavailable, Service temporarily unavailable, Internal server error, and for bulk download CSVs not found: <ids>, Total size <n> MB exceeds limit of 50 MB, and the ids / $filter exclusivity messages. 416 has an empty body — the information is in the Content-Range header.

def error_detail(resp):
    """Return a readable message for any error shape this API produces."""
    if not resp.content:
        return f"HTTP {resp.status_code}"
    detail = resp.json().get("detail")
    if isinstance(detail, list):
        return "; ".join(d.get("msg", str(d)) for d in detail)
    return str(detail)
